# Pre-registration v3: difficulty vs complementarity in routing

Written 2026-09-29 on top of commit `190cabd`, before any of the analyses below were run on the pairs
named here. It is frozen by the commit that adds it; the GitHub receive time is the external time stamp.
Any departure is reported as a deviation.

**Motivation.** An exploratory analysis of one pair (`notes/results.md`, "Pre-registered v2"; paper §5.4)
found three things:
- per-model success heads rank *discordant* prompts backwards (exactly one model right);
- the difference of the two heads carries some signal;
- routing on P(cheap) gains nothing.

This pre-registration tests whether the mechanism replicates on new pairs, and whether targeting
complementarity recovers routing gains.

**What has been seen (disclosure).**
- For the pair deepseek-v3-0324 → gpt-5-chat: everything, so it is excluded from every confirmatory
  endpoint below.
- For every pair: train-split accuracies, costs and oracle gains (`scripts/headroom.py`).
- For every model: within-category AUROC of its own success head (experiment T). No discordant-prompt
  statistic and no routing result has been computed for any pair listed below.

## Pairs (fixed by rule)

- **Rule.** Take the five pairs with the largest train-split oracle gain under the v2 selection rule
  (cost ratio ≥ 3, train accuracy(cheap) ≤ accuracy(strong), single named models), excluding the
  analyzed pair. Also include the paper's original pair.
- **Result:**
  1. deepseek-v3-0324 → gemini-2.5-flash (+0.085)
  2. deepseek-v3-0324 → glm-4.6 (+0.084)
  3. kimi-k2-0905 → claude-sonnet-4 (+0.082)
  4. deepseek-v3-0324 → claude-sonnet-4 (+0.077)
  5. qwen3-235b-a22b-2507 → claude-sonnet-4 (+0.074)
  6. deepseek-v3.1-terminus → gpt-5 (the original pair; +0.049)
- The pairs share models, so pair-level bootstraps understate dependence. Every per-pair result is
  reported as well.

## Common setup

- **Split and labels.** The same LLMRouterBench test split (1,328 prompts), label seeds (42, 999, 2024,
  2025, 3407) and label rule (record score ≥ 0.5) as the paper.
- **Budgets.** k ∈ {25, 100, 400, all}. A labeled prompt carries both models' outcomes, since a routing
  label requires running both.
- **Features.** Jev v1 question answers (cached) unless stated. Heads are per-model logistic regression,
  C = 1, as in the paper.
- **Discordant test prompts.** Exactly one of the two models is right. Label d = 1 if only the cheap
  model is right, 0 if only the strong model is.
- **Routing.** A policy sends a prompt to the cheap model when its score ≥ tau. Tau is chosen on the
  labeled prompts only (in-sample predictions): the best labeled quality with labeled mean cost ≤ the
  strong model's labeled mean cost. It is applied unchanged to test, as in pre-registration v2.

## Hypotheses

**H1. Mechanism replication (primary).**
- **Statistic.** The AUROC of P(cheap succeeds), from the Jev features head at k = all, for d on
  discordant test prompts.
- **Endpoint.** The mean over the 6 pairs, with a 95% CI from a bootstrap resampling pairs and, within
  each pair, discordant prompts.
- **Supported if** the CI upper bound < 0.5: success heads rank discordant prompts backwards.
- **Secondary.** The same at k = 25, 100 and 400; the same for the bge_knn and tfidf_logreg heads; and
  per pair.

**H2. Routing on relative capability (primary).**
- **Policies:**
  - **P-cheap:** score = P(cheap);
  - **Diff:** score = P(cheap) − P(strong), both from the same features.
- **Endpoint.** Test quality of Diff minus P-cheap at k = all, mean over pairs, with a bootstrap over
  pairs and test prompts.
- **Supported if** the CI lower bound > 0.
- **Secondary** (reported whatever the result):
  - Diff minus the best single model's test quality, and its cost;
  - k = 25, 100, 400;
  - the AUROC of P(cheap) − P(strong) for d on discordant prompts.

**H3. Pair-aware questions (secondary; one question set per pair).**
- **Generation.** An LLM (`claude-sonnet-5`, default settings, one sample per pair) writes 13 yes/no
  questions from the prompt below, with the pair's two model names filled in. It sees no benchmark
  prompts, outcomes or existing questions.
- **Format check.** As in v2: exactly 13 questions, ending in "?", ≤ 50 words each, no *benchmark* names.
  Model names are allowed here. If a set fails, regenerate once and log it.
- **Answering.** Jev `jev-1.13.0` answers each set on all 4,934 prompts, with the same text budget
  (16,000 chars) and head.
- **Endpoints:**
  - (a) The Diff policy's test quality with pair-aware features minus with v1 features, at k = all and
    k = 400, mean over pairs.
  - (b) Discordant-prompt AUROC of P(cheap) − P(strong) with pair-aware vs v1 features.
- No success threshold is set. Both are reported with CIs.
- **Budget.** Generator < $1; Jev ≈ 6 × $0.17; hard cap $3.

Generator prompt (verbatim; `{A}` = cheap model, `{B}` = strong model):

> Two language models, {A} and {B}, will each attempt the same user request: a conversation, possibly
> including an agent's earlier steps. The requests come from a mix of competition mathematics,
> programming problems, graduate-level science questions, general multiple-choice knowledge questions
> and software-engineering issues. Both models often succeed or fail together; what matters here is the
> requests where exactly one of them is right.
>
> Write exactly 13 yes/no questions about the request that a careful reader could answer from the
> request text alone, and whose answers would help predict which of the two models answers correctly
> when they disagree. Do not mention any benchmark. Return a JSON object mapping a short snake_case id
> to each question.

**H4. Label cost of complementarity (descriptive).**
- The share of labeled prompts that are discordant, by k.
- The discordant AUROC of the Diff score by k.
- No hypothesis.

## Reporting rules

- The analyzed pair (v3-0324 → gpt-5-chat) appears only as a labeled exploratory reference row.
- No question set is edited after its answers are requested.
